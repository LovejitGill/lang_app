# Project collaboration preferences

These instructions record the user's requested workflow for this project.

- The user handles Git staging, commits, tags, pushes, and other publishing or
  history-changing operations. Do not perform those actions or request access
  to perform them. Provide next-step commands with purpose, expected output,
  and verification instead. Read-only Git inspection is allowed.

- Whenever implementing a milestone, append its observed limitations and a
  practical optimization plan to `improvement_plan.md` before reporting completion.
- Start each milestone entry with `## Milestone N — Exact milestone name`.
  Preserve earlier entries and add dated progress updates for later improvements.
- Distinguish observed failures from untested risks and intentional scope limits.
  Include evidence, prioritized actions, and measurable verification criteria.
  If no limitation was observed, say so without claiming none exists.
- When giving the user command steps, include the command's intended purpose
  and typical use in no more than two sentences, key expected output, and what
  the result verifies. Label illustrative model output as variable.
- Keep implementation bounded to the requested milestone and explain the
  concepts being developed; do not advance into the complete application unasked.
